# PDA v2 架构设计

> 本文规定项目级边界。遇到未覆盖且会改变依赖方向、数据归属或持久化语义的设计，先提出方案并与 Operator 确认；功能内部的局部决策记录在对应功能文档中。

本架构设计的五个原则：
* Clean Architecture 分层设计
* 模块内部，层次单向依赖，数据单向流动
* 模块间不直接依赖
* 分层数据校验
* 设计保持空间，实现保持简洁

## 1. 组织方式

按功能组织代码，层次按需要设置，不为空功能创建占位目录。模块边界由公开入口和导入检查约束。

```text
lib/
  core/                 # 不含业务规则的通用能力
  features/
    ids/
    academic_course/
    custom_course/
    physics_experiment/
    other_experiment/
    timetable/
      domain/           # 业务数据模型
      repository/       # 业务用例所需的持久化和网络接口
      ports/            # 业务用例所需的其他 feature 的能力
      application/      # 用例与业务编排
      data/             # repository 接口的实现
      presentation/     # 提供页面、组件和界面交互状态
  integration/          # 创建对象、接线、跨模块适配
  main.dart
```

目录只说明职责，**不要求每个功能都有全部层次**。`core` 不能反向引用功能模块，共享设施若需要功能配置，由 `integration` 注册。

## 2. 依赖方向

| 层次 | 依赖的层次 | 说明 | 外部依赖 |
| --- | --- | --- | --- |
| `core` | 无功能模块 | 放稳定的公共契约和通用设施 | 公共契约仅依赖 Dart，通用设施可依赖数据库等外部库 |
| `domain` | 按需依赖 `core` 的公共契约 | 定义本功能的模型、规则和校验 | Dart 语言原生类型 |
| `repository` | 本功能的 `domain`，按需依赖 `core` | 声明本功能所需的持久化和网络能力 | Dart 语言原生类型 |
| `ports` | 本功能的 `domain`，按需依赖 `core` | 由消费方声明需要其他功能提供的最小能力，接口不暴露提供方的专属模型 | Dart 语言原生类型 |
| `application` | 本功能的 `domain`、`repository`、`ports`，按需依赖 `core` | 编排用例，依赖接口获取外部能力 | Dart 语言原生类型 |
| `data` | 本功能的 `repository`、`domain`，按需依赖 `core` | 实现持久化和网络接口；网络实现可单独成包 | 数据库、网络等外部库 |
| `presentation` | 本功能的 `application`，按需依赖本功能的 `domain` 和 `core` | 管理界面状态，共享业务数据由所属功能提供，页面不各存一份真值 | Flutter、状态管理库 |
| `integration` | `core`、所需功能的公开入口及消费方的 `ports` | 创建对象、实现跨模块 port 并委派给提供方；双方已使用同一公共契约时只接线，语义不同时在此适配 | 必要的外部实现或平台插件 |

功能模块之间禁止直接 import 或 export，包括对方的公开入口。消费方在自己的 ports 声明所需能力；顶层 `integration/` 从提供方的公开入口取得实现或查询，并注入消费方。适配器按消费端组织在顶层 `integration/` 下。

表中“按需依赖 core”对 domain、repository、ports、application 和 presentation 仅指纯 Dart 公共契约和值对象。数据库连接、文件和网络客户端等设施使用独立入口，供 data 或 integration 使用。导入检查应覆盖 import 和 export，例如 application 经公共入口间接取得数据库连接也算越界。

平台插件通过所属功能的 `data` 或 `integration` 接入，不进入领域规则。

## 3. 分层分粒度数据校验

校验按所需信息放在能作出判断的最内层。外部数据进入系统时解析一次，内部传递已验证的类型，不在各层重复猜测数据是否合法。

领域模型借用 SSA 的单次赋值思想：构造后不可修改字段，也不通过可变集合间接修改。状态变化创建新的模型，并重新经过构造校验；模型不提供 setter 或原地修改方法。

| 位置 | 校验粒度 | 失败处理 |
| --- | --- | --- |
| `data` 的解析与映射 | 检查网络响应、数据库记录或导入文件等外部数据的格式、必需字段及类型，再构造领域对象；不在映射代码中决定业务规则 | 损坏或无法表示的数据明确报错，不伪造默认值或空结果 |
| `domain` 与 `core` 的值对象 | 在构造时保证对象自身的不变量，例如起止时间有序、周次集合非空；不查询外部状态 | 拒绝构造非法对象 |
| `repository` 的实现 | 检查依赖当前持久化状态的规则，例如关联对象是否存在；由实际写入方保证校验与写入的一致性，本地数据库使用同一事务 | 需要原子性的操作不得部分提交；远端能力由接口契约和服务端实现保证 |
| 数据库约束 | 兜底保证非空、唯一性、外键和适合由数据库表达的基本范围；复杂结构由映射和领域对象继续校验 | 拒绝非法写入，不代替领域校验 |
| `application` | 检查跨操作的流程前提和转换能否成立；不重复持久化状态校验 | 阻止后续操作并报告可处理的失败 |
| `integration` | 对跨模块适配后的结果检查消费方契约所需的语义；双方共用同一公共契约时不重复校验提供方模型 | 保留接口约定的结果状态，不将失败伪装成成功 |
| `presentation` | 校验表单输入并反馈字段错误；提交后展示用例返回的失败，不自行判断依赖数据库状态的规则 | 保留用户输入，允许修正或重试 |

需要稳定引用的派生数据，由所属功能定义可重复的 ID 生成规则，并验证同一输入得到同一 ID、不同实体不会冲突；这不能只靠单个对象的构造校验。

## 4. 数据与运行时契约

- **数据归属：** 每类业务数据明确权威来源和所属功能。远端数据、本地缓存与界面状态各有用途；写入和失效规则由所属功能定义。相同上下文和生命周期的消费者复用只读查询、订阅或快照，不各自维护可写真值。页面与外部服务共用业务快照时，由所属功能的 application 公开只读查询或订阅，integration 按账号或应用生命周期装配和释放。首次读取不依赖页面打开。presentation 持有筛选、表单草稿等交互状态。派生数据由所属功能生成；是否缓存或持久化由实际需求和测量决定。
- **异步结果：** 读取和订阅按需要区分加载、失败、成功空数据与非空数据。结果携带足以核对其归属的上下文标识，例如账号或学期；上下文切换时取消旧操作或丢弃迟到结果。供异步外部写入的快照还需有可比较的版本或等效顺序标识。
- **外部输出：** 对会覆盖目标现有数据的操作，只有来源匹配且已就绪的结果才能用于替换；加载或失败不能被当作成功空数据。成功空数据如何处理，由目标契约定义。同一目标的并发写入按版本或等效顺序协调。需要持续同步的目标在失败后保留待同步状态，重试以最新结果为准且不得产生重复副作用。提醒、系统日历和原生 Widget 按各自契约应用这些规则。
- **迁移与账号边界：** 需要迁移历史数据时，先保全原数据，再按可恢复的单元校验和写入；中断后可重试，未完成时不得把部分结果当作完整数据。账号切换时隔离旧账号的任务、缓存和外部结果；退出时按数据保留策略清理，清理中断后能继续，不能让旧任务写回。
- **基础设施生命周期：** 共享连接等设施由 `integration` 创建、注入并关闭。功能的 `data` 使用注入的设施；功能专属的表、映射和读写规则仍归该功能所有，`core` 不反向导入功能代码。
